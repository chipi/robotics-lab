# Review of RFC-0031 (learning in the lab), 2026-11-26

The operator asked for a review of the draft RFC-0031 by the advisor (Fable 5.1). Read-only, in the
`mission-control` worktree at 224e7d5, plus `/work/robotics-evals`, `/work/microduck-nav`,
`/work/microduck-nav-runs` and the homelab recipe. Each finding is VERIFIED (the code path was read)
or SUSPECTED. Nothing was run.

## Verdict: accept option A, with changes to the data path, the promotion rule and the first slice

- Option A is right for the reasons the RFC gives, and B and C are rightly deferred or rejected. The
  mapping "training is a run on a resource" holds for the record (a request, states, artefacts, a
  verdict) and breaks for control (Mission Control can neither start, stop nor observe the trainer).
  The RFC should say it once and name the first version what it is: a request ledger plus an
  artefact import, not an adapter.
- One critical gap: the read-only slice has no data path. The registry is placed in Mission
  Control's store (Q2 A), the views in the Observatory, and nothing connects them.
- "Promotion is operator only" is not enforceable as written: the profile store records no author,
  identity is self-declared with tokens off, and the MCP allow-list carries `PUT
  /robots/{id}/profile/current`.
- The promotion rule "beats the rules on `success`" cannot fire on `avoidance_v1`: the rules arm
  scored `success` 1.0 there today.
- "Sim only until R8" holds at plugin load and in `lab-challenge`, not in the profile save, which is
  where the RFC places promotion.

## Data model

Separate table versus `goal_runs`: Q7 A, agree (`robot TEXT NOT NULL`, `target TEXT NOT NULL`,
`store.py:45-50`; goal-shaped readers `core.py:641-657, 681-683, 546-549`). Migration 4 to 5
(`SCHEMA_VERSION = 4`, `store.py:10`). It is a `training_requests` table. The registry is not a
store: the model record is derived from the training artefact (Observatory), replay and eval runs by
build, the eval summary (imported file) and promotions (Mission Control). If a stored document is
wanted, a CLI writes it into the Observatory's data folder with a contract test; never two writers.

## First UI slice

The unit is the training run, not the model. Order: (1) the record by hand for smoke, M1, M2a, M2b
(no code); (2) `libs/learning` schemas and the import CLI, with M1's folder as the fixture; (3) the
Observatory imports the folder and shows a training run page (headline curves from a JSON extracted
at import in microduck-nav's venv; the Observatory reads no tfevents); (4) the model page when the
first learned arm has a comparison. Mission Control's request form after the homelab's answer on a
machine interface, or as a ledger form with hand-set states.
